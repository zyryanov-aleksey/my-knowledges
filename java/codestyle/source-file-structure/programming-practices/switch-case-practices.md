# Использование switch-case

Главная цель `switch-case` конструкции - сделать ветвление кода понятным, структурированным и удобным для сопровождения.

Правила при выборе `switch-case` против `if-else`:

- Предпочитайте `switch` цепочкам `if-else`, если ветвление основано на сравнении одного значения с несколькими вариантами.
- Не усложняйте код использованием `switch` ради одного-двух простых условий.
- Используйте `if-else`, если условия содержат диапазоны, сложные логические выражения или независимые проверки.

## Правильный синтаксис

- Всегда использовать только современный синтаксис
- Обрабатывать все возможные значения, если это невозможно то использовать `default -> throw`
- Всегда использовать `default` ветку с выбросом исключения (`throw new IllegalArgumentException(..//msg..)`)
  Выбрасывать исключение необходимо **всегда**: если что-то пошло не так, сразу выбрасываем ошибку, а не продолжаем выполнение с некорректными данными (**Fail-fast**)

Правильные примеры:

```java
Status findStatus(int statusCode) {

    return switch (statusCode) {
        case 200, 201 -> Status.SUCCESS;
        case 404 -> Status.NOT_FOUND;
        default -> throw new IllegalArgumentException("Неизвестное значение %s".formatted(statusCode));
    };
}

String getMessage(StateEnum state) {

    String message = switch (state) {
        case NEW -> "New state;
        case DONE -> "Done state";
        default -> throw new IllegalStateException("Неподдерживаемый статус: %s".formatted(status));
    };
}

```

Почему `default -> throw` лучше универсальной (`default -> doSomething()`) обработки?

1. Не скрывает баги - неизвестное значение enum может означать ошибку в логике, которую универсальный default замаскирует.
2. Fail-fast - ошибка обнаруживается сразу, а не проявляется позже в неожиданном месте.
3. Явный контракт - код показывает, какие состояния поддерживаются, а какие считаются ошибкой.
