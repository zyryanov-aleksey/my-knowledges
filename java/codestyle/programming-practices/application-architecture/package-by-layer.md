# Слоеная/слоистая/package-by-layer архитектура

Слоеная архитектура замечательно подходит для небольших приложений или модулей на несколько классов
Но после разростания любого пакета более чем на 10 классов становится неудобной и в ней становится тяжело поддерживать навигацию и держать контекст.

## Структура package-by-layer приложения

Обязательная структура для каждого приложения представлена ниже на схеме
P.S.: если вы наткнулись на проект который структурирован по другому, то перестаивать ничего не стоит.

```
├── rest-api/                    # REST-контракт и DTO
│   ├── dto                      # DTO
│   │   └── ..Dto.java
│   ├── rest-controller/         # REST-контроллеры, обработчики ошибок
│   │   ├── ..RestController.java
│   │   └── ..RestExceptionHandler.java
│   └── ..RestApi.java           # REST-контракт
├── grpc-handler/                # gRPC-контроллеры/хендлеры, обработчики ошибок
│   ├── ..GrpcHandler.java
│   └── ..GrpcExceptionHandler.java
├── service/                     # сервисы с бизнес-логикой (бизнес операции, валидации, оркестрации, и т.п.)
│   ├── integration/             # интеграционные сервисы
│   │   ├── ..IntegrationService.java
│   │   └── ..IntegrationApi.java
│   └── ..Service.java
├── repository/                  # Доступ к БД, репозитории
│   ├── ..JdbcRepository.java
│   └── ..CrudRepository.java 
├── data/
│   ├── domain/                  # Внутренняя модель
│   │   └── ..Domain.java    
│   ├── entity/                  # Модель хранения
│   │   └── ..Entity.java 
│   └── const/                   # Константы, енамы
│       └── ..Enum.java
├── mapper/                      # Преобразования DTO, protobuf и внутренних моделей
│   └── ..Mapper.java
├── configuration/               # Spring-конфигурация и настройки
│   ├── properties/              # настройки переменных окружения
│   │   └── ..Properties.java    
│   └── ..Configuration.java     
├── scheduler/                   # Запуск задач по расписанию
│   └── ..Scheduler.java
├── batch/                       # Задачи Spring Batch
├── exception/                   # Исключения приложения
│   └── ..Exception.java
├── utils/                       # Вспомогательные функции
│   └── ..Util.java
└── ..Application.java
```

### Основной класс приложения

`..Application.java`, помеченный `@SpringBootApplication` должен обязательно находиться в корне приложения.
Является точкой входа в приложение. Рекомендуется его не менять, и аннотации над ним не ставить (лучше сделать это в отдельном классе конфигурации)

### configuration пакет

Пакет в котором находится конфигурация прилоежняи

### rest-api пакет

пакет в котором описаны rest-api контракты приложения
